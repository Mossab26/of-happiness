# دليل الفريق 4: فريق العمل والمساهمين
## Team 4 — Leadership & Development Teams

### 1. مسؤولية الفريق (Responsibility)
الفريق 4 مسؤول عن بناء قسم "فريق العمل" (`#team`)، مع الفصل الصارم والواضح بين:
1. **الإشراف الرسمي والتنظيمي المعتمد للنادي**: ويشمل المشرف العام الأستاذ ابن عيسى عاطف كمعلومة رسمية مؤكدة، وشارات "في انتظار التأكيد الرسمي" للمناصب التنفيذية الشاغرة.
2. **الفرق الطلابية السبعة لتطوير المشروع عبر GitHub**: وتوضيح دور كل فريق فرعي في بناء الكود المصدري ومهامه وفروعه البرمجية كنموذج تدريبي للمشاريع التعاونية.

### 2. الملفات المملوكة للفريق (Owned Files)
- `css/team-4-team.css`
- `js/team-4-team.js`
- `data/team-members.js`
- `teams/team-4/README.md`

### 3. ملفات ممنوع تعديلها (Restricted Files)
- `index.html` (مملوك للفريق 7).
- ملفات باقي الفرق في `css/` و `js/` و `data/`.

### 4. فرع Git المخصص (Git Branch)
```bash
git checkout -b feature/team-4-team
```

### 5. عقد التكامل والدوال (Integration Contract)
- يلتزم الفريق بتعريف الدالة:
  ```javascript
  function initTeamSection() { ... }
  ```
- تقرأ الدالة كائن `window.CLUB_TEAM` وتنشئ بطاقات الإشراف والفرق البرمجية داخل `<section id="team">`.

### 6. ضوابط الدقة والمصداقية (Accuracy Rules)
- لا تخلط إطلاقاً بين مطوري كود الويب (المساهمين عبر جيت هب) وإدارة النادي الرسمية.
- لا تختلق صوراً شخصية أو أسماء مزيفة لأعضاء الهيئة التنفيذية غير المعتمدين رسمياً؛ استخدم شارات شاغر/قيد التأكيد.

### 7. خطوات الاختبار والمعاينة (Testing Procedure)
1. فتح المشروع عبر Live Server.
2. فحص بطاقات المشرف والفرق السبعة على مختلف الشاشات.
3. التأكد من وضوح شارة التحقق الخضراء للمشرف المعتمد وشارة الانتظار للمناصب قيد الاعتماد.

### 8. المخرجات المتوقعة (Expected Deliverable)
- تصميم متناسق يعزز الشفافية والتعليم العملي لمنهجيات العمل الجماعي.
- فتح Pull Request بعنوان: `feat(team-4): organize leadership and github contributor teams`.
